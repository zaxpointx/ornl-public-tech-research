# Scouting: records, papers and artifacts (cyber and SWE), 2026-11-15

Scope. Round question: public ORNL cybersecurity and software-engineering projects outside the GitHub software catalog and the two 2026-11-11 snapshots. Surfaces covered on 2026-11-15: the DOE CODE documented search API (`/doecodeapi/services/search`, `site_ownership_code=ORNL`, paged through all 563 current records and diffed by `code_id` against `discovery/snapshots/doecode-2026-11-11.json`, which holds 544; 111 records are new to the snapshot, most of them older records the snapshot's all-fields query missed), plus keyword searches inside that set; the OSTI records API (`/api/v1/records`, `research_org=ORNL`, ten `q=` topic queries, then full single-record fetches for the hits used below); the arXiv export API; GitHub and GitLab repository metadata for code named in DOE CODE records; and GitHub repository search for code claimed or implied by papers. About 45 requests in total, a little over the 40 bound because the DOE CODE diff needed six pages. Each candidate was grepped against `discovery/catalog.csv`, `discovery/leads.csv` and both snapshots by name and URL. Candidates already present were skipped: pcapmunger, soar_survey_scoring, pyvnc_client, olcf/phoenix, smithy, systemburn, curifactory, experiment_orchestration, pygarden, the ornl-sava repos, benchmarking-unsupervised-online-IDS, Klokkos (as the sandialabs DOE CODE record) and WASP. No ORNL host was fetched. Two DOE CODE records point at code.ornl.gov repositories, and those were not opened.

## Top 3 for deeper study

1. **stripped-bof-llm.** The interesting mechanism is giving an LLM the program context that stripping destroys (stack objects, types, callers) before asking it to judge, rather than feeding it raw decompiler output. Depth: a 2026 journal paper with an accepted manuscript on OSTI, and Ghidra is open, so the context-recovery idea can be rebuilt and tested on small CTF-style binaries even without the authors' code. A builder learns how to frame binary vulnerability triage for LLMs and where decompiler noise breaks it.
2. **ot-llm-pentest.** This one sits squarely on cyber plus agents. It covers RAG over OT protocol documentation to make pentest agents competent on obscure ICS gear, and it adds commissioning, an unusual second use of the same agent. Depth: two OSTI reports, one an LDRD closeout, but no code. That suits a documented study, or a small reconstruction against a simulated Modbus or EtherNet/IP device, which `etherip` above could supply. A builder learns how domain retrieval changes agent tool use in a low-data protocol space.
3. **ai-atac-cyber-range with beyond-the-hype.** These pair a documented, reconfigurable evaluation range with public code that turns detector results into operating cost (MIT, runnable on the provided fake data). Depth: two runnable repos plus the range paper. A builder learns how to evaluate security tools fairly (repeatability, cost per alert), which also fits the catalog's cyberwheel and the snapshot's SOAR scoring repo.

Runners-up with the most runnable code: can-time-ids-benchmark (fits the existing CAN cluster) and dtlmod (an active SimGrid plugin for HPC workflow simulation).
