# INTERSECT project portfolio

This dossier fills in the individual public projects behind INTERSECT. The pages do not all describe the same kind of work. Some build science labs, some build the shared architecture, some build test environments, and some connect INTERSECT to real field or utility problems.

## Science projects

### Autonomous chemistry lab

ORNL describes a fully automated chemistry lab with precise robots, AI, chemical characterization, and electrochemical analysis. It is meant to run experiments around the clock and collect detailed records that can improve both scientific understanding and future AI models. The public page names polymers, ionic liquids, battery materials, and catalysts as example targets. [S42]

### AutoFlowS

AutoFlowS uses continuous-flow chemistry to design and carry out synthesis pathways. Its public project page describes a loop from hypothesis generation through experiment design, physical execution, analysis, and interpretation. [S31]

### Automated microscopy and 4D STEM

This project links electron microscopes at the Center for Nanophase Materials Sciences to ORNL high-performance computing. It plans a direct data path from the microscope to molecular-dynamics and density-functional-theory environments, structural reconstruction from 4D STEM data, and deep-kernel learning for physical discovery. [S44]

### ITAQPRO quantum edge node

ITAQPRO adds a quantum edge node to the INTERSECT system. The public description says it will connect a quantum computer, simulator, or accelerator to other INTERSECT edge nodes and HPC resources, including tasks from the Spallation Neutron Source and materials science. It also names AI and machine learning as a way to improve trapped-ion quantum control when labor and control electronics are limited. Chris Seck is listed as principal investigator. [S43]

### Autonomous additive manufacturing

The additive-manufacturing project uses robotics, in-process measurement, simulation, and applied mathematics to adapt metal printing. The public page says it connects MDF, OLCF, and SNS so one experiment can use manufacturing, computing, and neutron characterization together. [S50]

### AGILE grid laboratory

AGILE works on automating grid emulation at GRID-C. It combines real-time power-grid simulation, laboratory digital twins, control nodes, and low-latency data exchange. The public page names storage systems, solar generation, inverters, electric-vehicle chargers, loads, and transformers as equipment whose interactions need to be studied together. [S45]

### SMART Plant field systems

SMART Plant moves the self-driving-lab idea outdoors. ORNL describes an all-terrain robot that collects soil samples while aerial, ground, and belowground sensors send data to an edge computing station. The public project says the site included 200 poplar variants and that INTERSECT microservices supported real-time sample assessment and experiment steering. Udaya Kalluri is named publicly. [S49]

## Cross-cutting projects

### Open federated architecture

This project creates the shared design for INTERSECT. ORNL describes three parts: science use-case patterns, a system-of-systems architecture, and a microservice architecture. The goal is to connect instruments, robots, data, and computing with reusable interfaces. [S46]

### Integration project

The Integration Project is the test-and-assembly layer. It develops performance monitoring and virtualized infrastructure twins that imitate physical networks, instruments, and robots. The public page specifically names EPICS beamline modules, Nion Swift microscope emulators, and ROS robot interfaces as examples used in multi-site test environments. [S47]

### Software Development Environment

The Software Development Environment project aims to create a secure, reusable environment where researchers can reuse software components across scientific domains. Its public description emphasizes loosely connected services, interoperability, and universal solution libraries. [S48]

### Software deployment at facilities

This project addresses the less visible work of getting software to run reliably at DOE facilities. ORNL describes continuous integration and testing, SDKs, Spack, build infrastructure, containers, and a map of which applications and software products belong at which facility. [S51]

## What the portfolio shows

INTERSECT is not one robot and not one AI model. The public projects divide the problem into:

- science labs that generate new measurements;
- edge computing that reacts close to instruments;
- HPC resources that run larger analysis and simulation;
- shared data and software interfaces;
- virtual twins and testbeds that allow safe development;
- facility deployment and operations work;
- people who review, guide, and use the results.

The unusual connection is that the same architecture appears in a chemistry room, a microscope, a quantum system, a power-grid emulator, a field of plants, and a metal printer. The public evidence supports a shared design direction. It does not prove that every project uses the same software build or is connected in production.

## Unknowns

- The public pages do not disclose a complete component list or deployment map.
- They do not prove that all project goals have been achieved.
- They do not show private data, access credentials, internal network layouts, or facility safety procedures.
- They do not establish whether every named software component can be installed independently.
